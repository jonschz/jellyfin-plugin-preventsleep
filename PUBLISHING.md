# Publishing

Since we do not have CI for releases set up yet, the following manual process should be followed:

1. Decide on a new release version (following Semantic Versioning) based the most recent [public releases](https://github.com/jonschz/jellyfin-plugin-preventsleep/releases).
2. Set the new version in [Directory.Build.props](./Directory.Build.props) accordingly.
3. Open a pull request to apply the version changes.
4. On your local machine, create the release using `dotnet publish`. Verify that the version in the DLL file matches the expectations (Windows: Right Click -> Properties).
5. Do a brief manual smoke test on all available platforms: Install the new plugin build manually, start and stop a playback, verify that the expected log messages are shown.
6. Stable releases only: Create a zip archive consisting of the new DLL on the top level. Name the archive `Jellyfin.Plugin.PreventSleep_<version>.zip`, e.g. `Jellyfin.Plugin.PreventSleep_0.3.0.0.zip`.
7. Create a release on GitHub following the pattern of previous releases.
   - Append the DLL.
   - Stable releases only: Append the zip file from a previous step.
   - Be sure to set the attributes (pre-release vs. latest) correctly.
   - Double-check everything before publishing due to immutable releases.
8. Verify that the correct git tag was generated by the GitHub release process. Fix manually if needed.
9. Stable releases only: Add the new version to [manifest.json](./manifest.json), create a PR, and merge.
   - The `changelog` field supports Markdown.
   - The `checksum` is the MD5 sum of the zip file (use e.g. Git Bash and `md5sum` to compute).
   - You can test the new manifest version locally by running `npx http-server` in this repository and then adding a repository under `http://localhost:8080/manifest.json` to Jellyfin.
